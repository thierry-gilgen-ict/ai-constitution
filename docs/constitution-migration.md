# Controlled constitution adoption

Keep one canonical release, small native adapters and project overlays. Follow the host's actual instruction hierarchy and current authorized request. This procedure is for a coordinated migration; it adds no mandatory approval phrase to ordinary work.

1. Inventory selected machines/profiles/projects read-only. Record release, pin, scope, active work and unknown coverage. Historical audit examples are leads, not proof of current defects.
2. Separate shared defaults, project invariants, client-specific instructions, technical controls, current task state and archives. Preserve domain knowledge and evidence. Keep private organizational roles and incidents outside public source.
3. Prepare the canonical diff through the normal build/check pipeline. Preview one clean, disposable pilot and inspect rollback. A plan fingerprint is integrity evidence, not permission.
4. Apply only the authorized pilot. Verify files, fresh-session loading where actually performed, a representative behavior and owner acceptance separately. Record source, integrated revision and artifact provenance.
5. Use reviewed small waves. Recheck active work, pins, pauses, local edits and authorization at each wave. Prefer focused installation transactions to copying a large master prompt into repositories.
6. Retain explicit exceptions with an owner role and review date. Archive superseded evidence with links; do not delete dirty or historical work automatically. Failed verification leaves a held state and concrete next action.

Lightweight delivery needs focused evidence. Standard implementation adds meaningful behavioral and negative checks. High-risk work needs independent context and applicable technical release controls. A second agent on the same account supplies review evidence; it does not manufacture institutional independence or replace enforced gates.

Measure accepted useful outcomes, rework, integration delay and actual billable evidence when available. Smaller instruction files and cached-token counters alone establish neither savings nor quality. Keep task receipts and invoices private.
