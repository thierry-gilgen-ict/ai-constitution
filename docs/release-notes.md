# AI Constitution 0.7.1 — Workspace completion preview

Choose a project, review its setup and open Codex, Cursor or Claude Code. Hosted clients do not require a local model. This update completes the daily workflows introduced in 0.7.0.

- Request and retain a project readiness inspection. Installation, expected applicability, model access, qualification and client loading remain separate facts.
- Prepare a checkout, select toolkits and preview synchronization directly from its project home. Review retained activity for that target.
- Save toolkit and preparation edits privately; restore or delete candidates with concurrent-edit checks. Navigation and background refresh protect unfinished forms.
- Choose optional configuration mappings and architecture follow-up during onboarding. Resume or dismiss unfinished setup.
- Generate complete worker-owner access commands, with inference pairing and constitution permissions kept separate.
- Inspect durable operations, their recorded targets and times, and the supported recovery workflow. Older missing timing stays unknown.
- Use per-application launch evidence and account mappings. A hosted subscription quota does not block a qualified local route.

Existing enrollment, pins, pauses, grants, schedules and private state retain their meaning. New candidates do not publish or execute automatically. Native logins are never switched. The core remains dependency-free Python with build-free browser modules.

See the [workspace guide](projects-first-usability.md), [completion map](projects-first-completion.md), [illustrated manual](manual/README.md) and [upgrade guide](updates.md).

This remains an unsigned preview. Automated fixtures and packages are distinct from native client loading, physical worker/GPU acceptance and unfamiliar-user trials. Those [acceptance gates](compatibility-matrix.md) follow repository delivery. The optional autonomous project coding runner remains future work.
