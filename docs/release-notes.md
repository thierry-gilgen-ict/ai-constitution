AI Constitution 0.4.0 adds repeatable workspace workflows to Local Control.

- Inspect effective policy, route provenance, architecture and account mappings with separate evidence for installed files, client loading, model readiness and performance.
- Preview changes across enrolled repositories, apply one canary, preserve pins/pauses and recover individual project transactions.
- Prepare projects with reviewed dependency/runtime commands, private environment references, loopback health checks and inspected resume of interrupted steps.
- Build versioned rules, skills, prompt commands and MCP toolkits for Codex/Cursor while preserving unrelated settings. Export native manifests, Rulesync ZIPs and the documented Continue subset.
- Search project, model, architecture, account and toolkit metadata with Ctrl K/Cmd K. Secret contents and conversations are excluded.
- Review fresh account-wide quota evidence before launching a new local or native hosted session. Authentication and existing sessions remain client-managed.
- Pair controllers through an opt-in TLS listener with independent credentials and library/inventory/account scopes. Review three-way conflicts before staging changes.
- Export portable recovery recipes, explicitly map new-computer checkouts, retain architecture/toolkit choices and restore encrypted configuration separately.
- Repeat bounded local protocol/coding fixtures with pass counts, median duration, spread and matching regression fingerprints. No paid inference or arbitrary generated-code execution occurs.
- Enable resource schedules or executable-name triggers deliberately. Manual choices take priority, cooldowns prevent oscillation and active work is preserved. Gateway admission is fair per selected node.

Read the [workflow guide](https://github.com/thierry-gilgen-ict/ai-constitution/blob/v0.4.0/docs/workspace-workflows.md) and [illustrated manual](https://github.com/thierry-gilgen-ict/ai-constitution/blob/v0.4.0/docs/manual/README.md). Screenshots use synthetic data and explicit provenance. The Windows screenshot validator now reads Unicode HTML as UTF-8.

Existing 0.3 private state is preserved. New workflow files are additive schema-1 state; unknown schemas are refused without rewriting them. Keep private state and encrypted-backup credentials when upgrading. Use the existing verified update/rollback flow while managed and external clients are idle. Controller listeners and automation remain disabled unless explicitly enabled. MCP installation starts no server; verify actual client loading separately.

Reviewed release inventories, secret scanning before uploads, isolated native builds, SBOMs, checksums and provenance remain mandatory. Native companions remain unsigned preview builds. The standard-library core is unchanged; optional TLS retains cryptography>=50.0.2,<51 and its supported-host limitations.

Physical LAN/controller compatibility, GPU application triggers, sleep/wake, signing identities, a 48-hour availability soak and external usability remain separate [acceptance gates](https://github.com/thierry-gilgen-ict/ai-constitution/blob/v0.4.0/docs/compatibility-matrix.md). Hosted benchmarks and arbitrary-project execution are outside the bounded local lab. A quota observation cannot authenticate another account, Markdown cannot change a running model, and Local Control does not switch native Cursor Agent or pool distributed VRAM.
